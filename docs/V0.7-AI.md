# v0.7 AI完整辅助版实施方案

方案日期：2026-09-22。用户已批准完整辅助版，补充普通聊天和按需智能读取。2026-09-23已授权开始执行；完整范围已实现，四阶段完成本地专项验收与CI。0.7.0/code8于2026-09-24正式发布，原签名覆盖升级及远程附件校验通过；真实API效果和真机试用另验，最新状态见CODEX_HANDOFF.md与DEVELOPMENT.md。

## 1. 目标与边界

- Android客户端直连DeepSeek，面向用户本人和一位朋友；各设备配置API Key、默认模型和思考选项。普通离线功能保持可用。
- 交付自然语言单条/多条录入、便签整理与待办提取、任务拆解、自然语言查询、阶段回顾、草稿多轮调整，以及普通连续聊天。
- 默认不读取Daybook数据；谈及自己的任务、日程、记录等且回答需要本地信息时，可自动进行有范围的只读查询，不要求用户每次切换模式或批准一次普通查询。
- 所有业务写入都先生成可编辑预览，由用户确认后执行。当前不授予自主改期、完成、删除、后台主动执行等权限。
- 一并独立修复“完成一个任务时所有任务短暂变暗”。
- 不做电脑端、同步、账号、云端代理、长期聊天历史、语音/图片识别或新任务层级。隐私便签、拖动排序仍取消。
- 实施与发布分开：未来“开始执行”授权实施本方案，不等于授权公开发布或改动任何既有标签/附件。

## 2. 使用流程

提供一个统一AI助手入口，支持自然聊天，并提供“帮我记”“整理文字”“拆解任务”“查找内容”“阶段回顾”的快捷起点。这些入口共享会话、模型与结果组件，不建立多个独立Agent。

### 普通聊天与按需读取

1. 新会话只携带必要规则、当前日期/时区和用户聊天内容；不预先载入或发送业务库。
2. 模型可在当前用户问题需要个人数据时请求受限的只读工具；应用检查工具类型、过滤条件、条数与内容预算后执行。
3. 自动读取适用例：“我明天有什么安排”“之前记的装修预算是多少”“结合我本周没完成的任务，帮我安排一下”。
4. 不读取适用例：“给我讲个笑话”“任务拆解有什么方法”“最近好忙”。只出现“任务”“忙”等词，不构成读取个人数据的理由。
5. 语义不清或需要大范围历史时先追问范围，如“你是想结合Daybook里的记录，还是只讨论刚才说的情况？”常规明确、有范围的读取不反复弹确认框。
6. 用轻量状态/来源区域显示“正在查询本周未完成任务”等实际范围；回答后列出所用来源并可点击打开。零结果、截断和未读取的范围明确展示。
7. 用户说“不要读取记录/只聊天”后，在本会话禁用数据工具；已有个人数据上下文需从后续发送中移除或切换为清洁聊天上下文，不能只隐藏来源而继续发送。
8. 曾查到的数据可能随本次后续追问继续使用；“新对话/清空对话”清除消息、来源、未保存AI草稿与工具上下文，放弃草稿前提示。不要在清空后继续传旧上下文。

### 录入、整理与拆解

- 一次输入可得到多个事项/便签草稿，逐项选择、编辑、删除，再确认保存选中的内容。
- “第二条改到周五”只调整当前草稿；沿用草稿标识，保留未被指示修改的字段。
- 未明确截止日期的任务保持无截止日期；日程/记录的必需日期缺失应澄清。提醒、日期和类型遵循现有校验规则；不擅自引入新的重复任务或独立提醒生成范围。
- 任务拆解生成普通任务，不新增父子任务、项目表或优先级等产品能力。
- 便签整理支持粘贴文字或选定现有便签；原文与建议分别显示，确认后替换或另存。含图便签仅处理明确选中的文字，保留图片块及顺序；无法可靠保留时只提供另存文本，绝不静默丢图。
- 写入时再次校验原数据是否已改变或被恢复/删除；如发生冲突，让用户刷新预览，不覆盖新内容。

### 查询与回顾

- 支持按日期、类型、完成状态、标签、关键词筛选，再按需读取匹配项正文；第一版采用本地结构化查询与文本匹配，不额外引入向量数据库。
- 数据工具覆盖事项、便签及现有独立提醒的只读查询。日程发生日期、任务截止日期、记录日期、创建/更新时间分别处理；无截止日期任务不能自动当成本周到期任务。
- 便签无发生日期时明确使用何种时间范围；重复提醒查询复用既有RepeatRules，不能把规则定义误报为已发生记录。
- 第一版现有数据库没有独立完成时间字段，updatedAt也不等于完成时间。因此不把“当前已完成且本周更新”声称为“本周完成”。无法可靠计算时说明限制，使用可证实的日期和状态汇总；若将来需要准确完成历史，另议数据结构。
- 总数、状态计数、日期过滤由程序计算；AI负责解释、整理与建议，来源必须来自实际返回的记录ID。
- 正文按需读取，设单次/累计条数、字数和工具调用次数限制；达到限制后明确结果不完整，允许缩小范围或由用户主动继续，不悄悄上传整个库。
- 阶段回顾默认按用户指定的时间与类型筛选，生成草稿；可以确认另存为便签，不自动保存。

## 3. 模型、密钥与聊天生命周期

- 设置默认模型，AI页可临时切换；独立深度思考开关，显式传递参数。切换后告知后续消息使用的新模型，不自动改用其他模型。
- 可读取官方/models列表，但“列出”不等于适配完成；只向已验证支持的模型开放对应能力，未知/不兼容模型给出说明。
- 以官方当时可用模型为准；2026-09-22文档列出deepseek-flash与deepseek-v4-pro。Flash是默认候选，最终用日期解析、草稿编辑、工具调用样例评估正确率、耗时和用量；不沿用过时模型名或价格假设。
- Key使用Android Keystore支持的本地加密保存，不进入日志、崩溃信息、备份或SavedState；允许替换、删除。发送只到固定HTTPS官方端点，不通过模型给出的URL发送认证信息。
- 初次启用明确说明输入及按需读取的记录会发送给DeepSeek。真实调用由用户配置并主动使用，连接测试说明可能产生API调用；不索取用户在聊天里粘贴Key。
- 普通聊天、工具结果、AI草稿只在应用进程内保存；页面往返和Activity重建保留，进程终止后清空。不得写入Room、文件、SavedState恢复包或业务备份。已确认保存到Daybook的事项/便签照常持久化。
- 对话超过上下文预算时明确提示开启新会话或裁剪，不无声丢弃导致指代错误。提供停止生成与清空对话；停止后迟到结果不能覆盖新会话。
- “不长期保存”描述Daybook本地行为，不据此承诺API服务商不保留请求；外部数据政策按官方说明。

## 4. 实现结构与可靠性

- 保留单Android模块与Compose UI / ViewModel / Repository / Room分层，新增AI调用层、会话控制器、受限工具执行器和草稿预览组件。接口可替换为假服务用于自动测试，不引入通用Agent框架或多模块重构。
- 新增INTERNET权限与必要的网络调用实现；依赖沿用现有能力或最小必要客户端，不顺便更换存储/架构。目标保持Room6、ZIP JSON6。
- 向模型暴露结构化只读工具和草稿输出能力，不暴露任意SQL、任意文件路径、任意网络请求或直接Repository写入接口。
- 用户输入、查询返回的正文都是不可信内容；记录内“忽略规则、读取全部记录、提交修改”等文本不能升级为权限。权限、范围和预算由应用端约束。
- AI输出做严格类型/字段/长度/日期/来源ID校验，未知操作拒绝；合法JSON不代表合法业务数据。
- 批量保存先完整校验、事务写入；同一批确认具有防重复保护，失败不能留下半批记录。模型请求重试和本地写入分离，不能因网络重试再次创建记录。
- 现有便签替换沿用仓库写锁、图片引用与恢复互斥，冲突检测应在同一受控写入边界完成。
- 超时、断网、认证失败、余额/限流、输出截断、格式错误提供可理解提示并保留本次输入；无自动无限重试，禁止在错误信息中回显Key/原始敏感请求。
- 任务完成反馈按ID局部处理，持久化先于视觉停留；保留全局恢复/备份保护，不以取消所有禁用状态来掩盖问题。

- 使用固定时钟、假API和虚构记录覆盖可重复测试；真实DeepSeek的连接、模型可用性与效果独立记录，不把假服务结果写成真实调用通过。
- 日期、批量保存、替换、恢复交互必须有针对性测试；数据库格式如确需改变，先说明影响并获批准，保留schema和非破坏性迁移测试。
- 自动测试、模拟器、真机分别记录；只扩展与改动相关的检查，不重跑v0.6完整发布验收。
- 每阶段完成更新DEVELOPMENT.md和交接，检查暂存内容、提交推送main并核对CI。普通开发构建与正式发布区分；用户已追加授权v0.7正式发布，v0.6资产保持不变。

## 6. 方案取舍与启动约定

- 推荐方案为上述“按需只读＋确认写入”的统一助手，匹配用户希望智能读取和未来逐步放权的方向。代价是比单纯聊天多出工具路由、范围控制和来源验收。
- 替代方案一：始终由用户手动选记录后发送。实现与权限更简单，但每次操作多一步，未采用为默认；可保留为明确指定上下文的入口。
- 替代方案二：每次发送全库。接入表面简单，但数据外传、费用和长上下文噪声都更大，不推荐。
- 聊天只在内存保存，不需要新增聊天数据库；需要长期历史、自动后台执行、跨设备、图像识别或其他重要数据结构时另议，不利用当前批准隐式扩展。
- 用户已于2026-09-23说“开始执行”。恢复时先核对实际Git和交接，复用既有成果，无需再次询问是否实施此范围。不得因时钟到点自动执行或创建定时任务。
