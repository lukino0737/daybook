# 第二阶段：提醒与标签回顾

## 里程碑 A：本地提醒

- 安排、任务可选一个独立的本地提醒日期时间；生活记录不提醒。截止时间与提醒时间互不替代。
- 默认不提醒；主动开启时请求通知权限。Android 12+ 引导开启准时提醒；未授权时明确显示尚未启用，不静默降级为延迟闹钟。
- 保存后由数据库驱动系统调度。编辑、删除、完成、撤销、恢复后重建调度；通知打开对应记录。
- 重启、应用更新、时区/时间变化、权限恢复后重新核对。已发出的提醒不重复；过去 24 小时内遗漏的提醒补发并标注，超过 24 小时不补发。
- 拒绝权限不影响记录保存；应用内提供设置入口。系统强行停止后须重新打开；各品牌后台限制需真机试用。
- 数据库 v1 → v2 保留全部原字段；JSON v1 可导入，新格式完整校验并往返一致。
- 验收：日期规则单测；真实 v1 schema 迁移测试；通知发送、点击、取消、去重与权限检查；回归备份失败路径。

## 里程碑 B：标签与回顾

- 每条内容最多 10 个标签，每个 1–30 字，去除首尾空格与重复项。
- 回顾按日期倒序列出生活记录，可切换全部类型；按一个标签筛选，搜索标题和正文，两者取交集。
- 编辑可输入或选择已有标签；卡片显示标签；筛选结果可直接编辑。
- 标签、提醒随备份保存，升级迁移保留原数据。空结果、长正文、大字体可用。
- 验收：筛选与排序、标签校验、备份兼容和迁移、编辑与回顾界面测试。

## 界面约定

用户确认优先手机竖屏，主界面请求固定竖屏，不设计横屏布局；仍验证大字体、软键盘和系统重建后的草稿保留。

## 交付

分别完成 A、B 检查后提交并推送 main；发布 v0.2.0 同签名 APK，验证真实 v0.1.0 覆盖升级。
模拟器与真机结果分开记录。生日重复、照片、背景、生理期专用界面留待后续。

实现依据：[Android 系统闹钟](https://developer.android.com/develop/background-work/services/alarms)、[通知运行时权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)。使用单个待触发系统闹钟，触发时从数据库重新核对全部到期提醒；不使用常驻后台服务。
