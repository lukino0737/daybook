# 跟着 Daybook 练 AI coding

## 先看一次保存

```mermaid
flowchart LR
    A[编辑表单] --> B[ViewModel 保存草稿]
    B --> C[Entry 校验]
    C --> D[Repository 写入]
    D --> E[Room 数据库]
    E --> F[Flow 通知界面更新]
```

先回答三个问题：标题空白在哪里被拒绝？写入失败为什么不会关闭表单？为什么修改后仍然是同一个 ID？沿着 `EntryEditor`、`DaybookViewModel.save` 和 `EntryRepository.save` 阅读即可。

## 再看日期

`EntryRulesTest` 是明确的验收约定。尝试先预测“只有日期的 DDL 在当天 23:59 是否逾期”，再阅读规则实现。区分截止日期、发生日期和记录日期，不引入没有需求的时间字段。

## 最后看恢复

阅读 `BackupCodecTest` 与 `RepositoryTest`。特别关注：校验失败发生在数据库修改前；数据库清空与插入处于同一事务；快照写不成功就不替换数据。测试中的 SQLite 触发器故意让插入失败，用来证明回滚行为。

## 每次贡献的工作方式

1. 从真实使用中选择一个小问题，写清修改前后行为。
2. 请 AI 先找相关代码和风险，自己确认验收条件。
3. 阅读核心改动，不必逐行研究所有框架代码。
4. 执行相关测试，检查暂存文件，记录结果后提交。

可作为后续练习的题目：无日期任务的排序、记录搜索、重复课程的单次取消。先选一个，避免同时增加多个子系统。
